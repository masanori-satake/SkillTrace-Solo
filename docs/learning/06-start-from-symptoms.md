# 06. 現象から引く — おかしいと感じたら、まずどこを見るか

## この文書で分かること

- スキルを使っていて感じる不便さ（現象）から、SkillTrace の
  どの表示を最初に見ればよいか
- 現象の裏で何が起きているかの当たりの付け方
- 詳しい切り分けと対処は 07、数字の読み方は 04、直し方は 05 へ
  進むための入口

> 実例の phase0-probe / kiro-probe は、著者が検証用に作って自分の
> 環境でだけ動かしたダミースキルです（このリポジトリには含まれて
> いません）。出どころは[索引](README.md)の「実例の出どころ」を
> 参照してください。

## この文書の使い方

スキルへの不満は、たいてい「構造の問題」ではなく「効用が出て
いない」という現象として現れます。応答が遅い、読んでくれない、
消費が多い——その感覚は正しい出発点です。あとは、現象の裏で
何が起きているかを SkillTrace の表示で確かめるだけです。

この文書は索引です。下の表で自分の現象を見つけ、最初に見る
表示を開いてください。切り分けと対処の本体は
[07](07-troubleshooting-by-symptom.md) にあります。

## 見る前に知っておくとよいこと

- **「記録なし」は「読まれていない」ことの証明ではありません。**
  記録の形式が変われば対応付けに漏れが出ます。判別の言い方も
  「記録からは読み込まれた形跡がない」までが正確です（04）。
- **推定と実測を混ぜない。** ファイルの推定トークンは目安、
  セッションの実測（トークン／クレジット）は記録された使用量
  です。なお、トークン数は使用量であって支払額そのものでは
  ありません（新規入力・キャッシュ・出力で単価が異なります）。
- **判別結果は渡せます。** ツリーコピーやサマリの文書コピーで、
  見た表示そのものを作り手に渡せます。「重い気がする」ではなく
  「このセッションでは開始時点で使用率がこれだけあった」と
  渡せるのが、このツールで判別する意味です。
