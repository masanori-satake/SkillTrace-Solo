# エージェントの仕組みを理解する — SkillTrace 学習ドキュメント

SkillTrace（Copilot / Kiro のスキル読み込みを可視化するツール）に出てくる言葉を手がかりに、
LLM エージェントの仕組みを理解するための読み物です。

進め方の約束:

- **ツールの画面に出てくる言葉から入る**。抽象的な概念論はしない。
- **実例は全部、本物のセッションの実測値**を使う（出どころは次節）。
  再現実験の方法も付ける。
- 1つの概念につき1ファイル、10分で読める長さにする。

## 実例の出どころ（先に知っておいてほしいこと）

このシリーズに繰り返し出てくる **phase0-probe** と **kiro-probe** は、
著者（SkillTrace の開発者）が検証のために作り、自分の PC で動かした
ダミースキル（プローブ）の名前です。

- 中身は「SKILL.md から references を辿って、奥に書かれた合言葉を
  答える」だけの最小のスキルです。phase0-probe が Copilot 用、
  kiro-probe が Kiro 用です
- 著者以外の人は動かしていませんし、このリポジトリにもツール本体にも
  含まれていません。読者の環境で開いたり実行したりするものでは
  ありません。各文書に出てくる実測とは、この2つの実行記録のことです
- 全編の数値は、原則としてこの2セッションの実測の使い回しです。
  バラバラの事例集ではなく、同じ記録を角度を変えて読み直す構成に
  なっています。数値の詳細は、この索引の末尾の「基礎データ」に
  まとめました

大事なのは数値そのものより「記録のどこに、どう出るか」で、そこは
読者自身のセッションでも同じです。自分のスキルを SkillTrace で
開けば、同じ種類の数値が同じ場所に並びます。

## 動画解説

このシリーズの背景にある、LLM のコンテキストの仕組みを動画でも解説しています。
コンテキストへの読み込みの仕組み、トークンとクレジットの消費、コンテキストが
長くなるほど精度が落ちる問題（Context Rot、Lost in the Middle）と、その対処
（プロンプトキャッシュ、compaction、階層メモリ）までを扱います。
Gemini Notebook（NotebookLM）で生成した動画とスライドです。

- 動画: [Context Engineering: The Architecture of LLM Attention and Memory](https://youtu.be/Tu9frpRp8OA)（YouTube）
- スライド: [PDF](media/LLM_Context_Engineering.pdf) / [PowerPoint](media/LLM_Context_Engineering.pptx)

## 実例セッションの基礎データ（全編で使う）

合計4ファイル・推定合計629トークン）を Copilot に実行させた記録:

- 4ターンで回答完了。ツール実行5回

- 到達: SKILL.md・alpha.md・beta.md は確度高（コンテキストへの読み込みを確認）、スキル外の probe-note.md は確度中（読み取り）

## 実例セッションの基礎データ（Kiro 側、03 で使う）

合計3ファイル）を Kiro に実行させた記録（03 の対比用）:

- 1ターンで回答完了。ツール呼び出し8回（探索4・開示1・読み取り3）
